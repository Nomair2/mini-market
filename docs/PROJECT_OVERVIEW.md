# NEXUS Market — نظرة عامة على المشروع

**الإصدار:** V1 | **المالك وصاحب القرار:** المالك | **المدير التقني:** Claude 1

## 1. الهدف
نظام متكامل لإدارة Mini Market يعمل فعلياً في متجر حقيقي، يبدأ بمتجر واحد، ويُبنى بحيث يمكن لاحقاً تحويله إلى منتج تجاري متعدد المتاجر.

## 2. القرارات المعتمدة (من المالك)
| البند | القرار |
|---|---|
| المنصة | Android |
| الأجهزة في V1 | جهاز واحد |
| المستخدم | المالك فقط |
| السوق | سوريا |
| العملة | الليرة السورية SYP، صفر خانات عشرية، تُخزَّن INTEGER |
| الضرائب | لا توجد في V1 |
| البيع الآجل | مدعوم |
| اللغة | العربية فقط مع RTL كامل |
| الباركود | كاميرا الهاتف |
| الفواتير | PDF + مشاركة عبر WhatsApp |
| التشغيل | Offline-first |
| قاعدة البيانات | SQLite عبر Drift (مصدر الحقيقة) |
| الحزمة التقنية | Flutter, Dart, Drift, SQLite, Riverpod, GoRouter |
| Firebase | نسخ احتياطي ومزامنة **اختيارية** عند توفر الإنترنت |
| Django | غير مستخدم في V1 |

## 3. القرارات المعمارية الإلزامية
Repository Pattern • UnitOfWork للعمليات الذرية • UUID • `Money` و`Quantity` بأنواع دقيقة • لا `float`/`double` للحسابات • مبالغ صحيحة بالليرة • لا حذف للفواتير والقيود والحركات المعتمدة (إلغاء/مرتجعات/قيود عكسية) • منع المخزون السالب افتراضياً • المتوسط المرجح المتحرك • حفظ تكلفة المنتج وقت البيع • كل تعديل مخزون = حركة مخزون • كل عملية مالية = قيود متوازنة (مدين = دائن) • عمليات البيع/الشراء/المرتجعات ذرّية في معاملة واحدة • `store_id` منذ البداية • لا تعدد متاجر ولا اشتراكات في V1.

## 4. نطاق V1 (داخل / خارج)
**داخل:** المنتجات والفئات والباركود • المخزون والجرد • نقطة البيع والفواتير والمرتجعات والإلغاء • العملاء والبيع الآجل والتحصيل • الموردون والمشتريات والمرتجعات والدفع • المصروفات • المحاسبة (قيود، ميزان مراجعة، أرباح) • التقارير • فاتورة PDF ومشاركتها • الأرصدة الافتتاحية • النسخ الاحتياطي.

**خارج V1:** تعدد المتاجر والاشتراكات • الضرائب • أدوار وصلاحيات • عدة أجهزة • تواريخ الصلاحية والدفعات • عملات متعددة • اللغات الأخرى • Django/خادم.
